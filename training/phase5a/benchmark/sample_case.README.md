# sample_case.json

This file illustrates the exact JSON shape that held-out falsification benchmark cases must follow. It is **not real benchmark data** — it is a format-reference fixture only, committed to the repository for documentation purposes.

**CRITICAL EVALUATION-INTEGRITY REQUIREMENT:** The real held-out benchmark must be supplied by the human operator and must **NEVER** be:
- Generated by `generate_candidates.py`
- Derived from the training dataset
- Committed to this repository

The benchmark is the independent ground truth against which the trained model's verdict accuracy will be measured. It must remain completely separate from the train/valid/test split produced by `split_dataset.py`.

**Ground truth is entered and locked in the Dashboard, not the import file (Test 1 evaluation-stage addendum).** An imported case, like the one in `sample_case.json`, deliberately carries no `humanVerdict`/`humanDimensions` — those default to "not yet labeled" on import. The operator opens the Dashboard's Benchmark page, enters the semantic verdict and observable-behavior dimensions for each imported case under "Ground truth," and clicks "LOCK GROUND TRUTH." Once locked, `groundTruthLocked` is `true` and `humanVerdict`/`humanDimensions` cannot be changed through the normal UI again — see `spec/schema/trial4-benchmark-case.ts` and `Trial4BenchmarkService.lockGroundTruth`. Only a locked case is eligible to run (`Trial4BenchmarkService.runNextCase` skips any unlocked case). `humanVerdict`/`humanDimensions` are **never** sent to any model (`Trial4BenchmarkService.judgeWithRole` destructures only `kind`/`originalText`/`finalText`/`beforeContext`/`afterContext`) and **never** shown to the operator before they submit acceptability/rank judgments for a case — see `spec/schema/trial4-benchmark-result.ts`. Locked ground truth is what `computeTrial4BenchmarkStats` uses to compute Test 1's primary metric (5-way semantic verdict exact accuracy) and the secondary dimension exact-set/micro-F1 metrics.
